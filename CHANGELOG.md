# Изменения

## Не выпущено

- Безопасность (по внешнему разбору): IMAP проверяет сертификат и имя сервера (`imap_verify = false` отключает), таймаут 30 с; разбор тела письма линейный и ограничен 200 тыс. символов; сначала проверяется беседа, потом пользователь (чужая беседа не получает ответов); отказы не чаще раза в минуту на беседу; пароль закрывается и в экранированном виде (repr, json); логин и адрес не могут начинаться с `-`, перед адресом в ssh стоит `--`; `TELEGRAM_API_URL` только https (или localhost); устаревшие команды Telegram (старше 5 минут) пропускаются; `*.bak` и `.env.*` в `.gitignore`.
- SECURITY.md: модель угроз, хранение секретов, что уходит в мессенджер, известные ограничения, что делать при утечке.
- Чистка: общий делитель сообщений, удалён неиспользуемый `Daemon.scheduler_loop`, сильнее фильтр управляющих последовательностей (OSC с ST), поправлены комментарий `allowed_chats` и текст ошибки отправки.
- Состояние машин из беседы: `/uptime`, `/disk`, `/mem`, `/top`, `/cpu`, `/net` по одной цели или по всем сразу. Включается у цели (`info = [...]`), свои слова в `[targets.<имя>.commands]`; произвольный текст из беседы не выполняется, ответ на 15 секунд кэшируется, один запрос на цель одновременно.
- Исправлено: в интерфейсе правка цели теряла таблицу `expect` у других почтовых целей и мешала сохранению.
- Юнит systemd: `UMask=0077`, пустой набор capabilities, ограничения ядра и сокетов (`systemd-analyze security`: 5.8 -> 3.7).
- `pip-audit` в CI, GitHub Actions на версиях под Node 24.
- Тесты: обрыв шлюза посреди сеанса, вложенное MIME-письмо.
- ROADMAP.md, правила выпуска в CONTRIBUTING.md.
- Безопасность: маркеры вывода случайные, имя файла в проверяемой папке (например `__HUB0_END__`) больше не обрезает листинг.
- Команды принимаются только из своих бесед (основная, `EXTRA_PEERS`, `peers` целей) или из `ALLOWED_CHATS`; в чужих бот молчит, отказ пишется в лог.
- Python 3.10 снят с поддержки (нужен 3.11+); `pip-audit` работает на всех версиях матрицы.
- CI: `REQUIRE_SSH=1` (без ssh тесты падают, а не пропускаются), покрытие считается с ветками (88.7%).

## 1.1.0

- Цель `type = "mail"`: отчёт по письмам из IMAP, ожидаемые машины по дням недели, ночное окно, дата в команде.
- Вход напрямую по ssh (`via = "ssh"`) и свой PAM-шлюз у цели (`pam_host`, `pam_port`).
- Выбор мессенджера: ВКонтакте или Telegram (`MESSENGER`), общий интерфейс для новых.
- Свои команды на каждую цель, `/run <цель> [аргументы]`.
- TUI: правка всех полей и общих настроек, командная строка `>`, срочный просмотр папки (`/ls`), живой просмотр (`/live`, `/top`).
- CLI: `ls`, `live`, `check --date`, `--no-chat`.
- Название вкладки терминала показывает ход и итог проверки.
- Документация: README (ru, en), docs/PAM.md, docs/TROUBLESHOOTING.md, SECURITY.md, CONTRIBUTING.md.

## 1.0.0

- Цели в `targets.toml`, пароли в `.env`; проверка конфигурации до любого сетевого действия.
- Движок проверки: один вход на цель, все пути за сеанс, `sudo -n` по флагу, три стиля отчёта.
- Демон: расписание, команды из беседы ВК, отдельный поток и лок на цель, сторож
  времени, ограничитель входов на шлюз, systemd-юнит и установщик.
- TUI на Textual: цели, редактор, проверка с отправкой и без, проверка путей, статус.
- CLI: `validate`, `list`, `check`, `check-paths`, `tui`, `run`, `start`, `stop`,
  `restart`, `status`, `logs`.
