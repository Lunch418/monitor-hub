# Если что-то не работает

Любая ошибка проверки приходит в беседу короткой фразой без паролей. Подробности и трассировка - в логе:
`./monitor-hub logs -n 100`. Цели изолированы: сбой одной не останавливает остальные.

| Симптом | Причина и что делать |
|---|---|
| "Не удалось пройти этап на jump-хосте" | шлюз недоступен или другой диалог; проверьте `PAM_HOST`, порт, сеть, см. [PAM.md](PAM.md) |
| "на машине" | шлюз пустил, а цель не ответила: адрес в `target_host`, права учётки |
| Неверный пароль | проверьте переменную из `password_env` в `.env`; пароль с пробелами и кавычками берите в кавычки |
| Пустой или странный список | формат `ls -la` на машине отличается (другая локаль, busybox); `check-paths <цель>` покажет, видны ли папки |
| "нет такого пути" / "нет доступа" | путь указан неверно или нужен `sudo = true` (работает только `sudo -n`) |
| ВК: ошибка токена | протух ключ сообщества или нет права на сообщения; создайте новый и обновите `VK_TOKEN` |
| Telegram: 401 или 404 | неверный `TELEGRAM_TOKEN`; бота нужно добавить в чат и проверить `TELEGRAM_CHAT_ID` |
| Бот молчит на команды | пользователь не в `ALLOWED_USERS` (или `ALLOW_ANY_USER=1`); пользователи Telegram - числовые id |
| IMAP: ошибка входа | проверьте `imap_host`, порт, `imap_ssl`, пароль приложения |
| IMAP: `certificate verify failed` | у сервера самоподписанный или просроченный сертификат или имя не совпадает с `imap_host`; исправьте сертификат, либо (только в доверенной сети) задайте `imap_verify = false` |
| Письма есть, а в отчёте "нет письма" | письмо вне "ночного" окна (`night_from`, `night_to`) или имя машины не в теме (`subject_re`) |
| Проверка не пришла по расписанию | демон был остановлен: пропущенные запуски не наверстываются; время берётся по часовому поясу машины |
| Правки не применились | демон читает конфигурацию при старте: `./monitor-hub restart` |
| Сеанс завис | ввод подталкивается автоматически (`PROMPT_NUDGE`), по `run_timeout` в беседу придёт предупреждение |

Проверить всё без сети: `./monitor-hub validate`.
